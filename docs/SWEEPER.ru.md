# «Сборщик» и тестовый стенд — технические подробности

**[English version →](SWEEPER.md)**

Подробное описание вкладки «Сборщик» (как считается газ, газовый автобус, порядок транзакций) и запуска на локальных тестовых сетях.

## Вкладка «Сборщик»

Собирает остатки с твоих кошельков на один адрес. Подписывает и отправляет **сама страница в браузере**, после
твоего подтверждения. Локальный сервер в этом не участвует: он не получает ни ключей, ни транзакций.

1. **Куда собрать.** Введи адрес получателя, порог (по умолчанию $1) и запас на рост газа (по умолчанию 50%).
   Выбери RPC: публичные (publicnode, официальные RPC сетей) или Alchemy с ключом из «Настроек».
2. **План (пробный прогон, ничего не отправляет).** Кандидаты берутся из последнего скана: только монеты с ценой,
   без спама и без скрытых. Для каждой пары «кошелёк × сеть» с живого RPC читаются балансы и считается газ:
   - ERC-20: `резерв = ceil(estimateGas × 1.2) × maxFee` (+ L1 data fee × 1.5 на OP-стеке и Scroll);
     отправляется, если `стоимость − резерв ≥ порога`.
   - Нативная монета (последней): `баланс − резервы токенов − 21000 × maxFee (− L1 fee × 1.5)`;
     отправляется, если остаток ≥ порога.
   - EIP-1559: `maxFee = base × (1 + запас) + tip`. Legacy (BNB): `gasPrice`, кошелёк обнуляется ровно до 0.
   - Arbitrum и ZK-сети (zkSync, Abstract, Lens), а также получатель-контракт: лимит газа = оценка × 1.3,
     потому что в оценку входит L1/pubdata-часть.
   - Сверху плана — сводка по каждой сети: сколько кошельков (и на сколько $) «только нативка, платит сам»,
     «токены + газ есть», «токены, газа нет», «нечего слать».
   - Без газового автобуса кошелёк «токены, газа нет» получает пометку «нужен газ» и сумму, которую надо докинуть.
   - Итог «Придёт на адрес» = стоимость токенов + отправленная нативка (газ токенов уже вычтен из нативки).
   - Строка сверки под итогами: «в панели $X · в плане $Y до газа · не вошло: …» — мелочь дешевле порога,
     снятые сети, пропущенное с причиной (газ дороже, нет газа и возить не выгодно, …), изменение балансов после скана.
     Сумма плана и «не вошло» равна сумме в панели.
3. **🚌 Газовый автобус** (галочка, по умолчанию включена). Кошелёк с токенами, но без газа, получает газ
   от кошелька этой же сети:
   - Автобус по умолчанию — кошелёк, у которого больше всего свободной нативки (после его собственных переводов).
     В заголовке сети его можно сменить, в том числе на самого получателя — тогда нужен и его ключ.
   - Привозит ровно `газ на его токены + газ на возврат остатка − что уже есть`, плюс 10% запаса.
     При отправке сумма пересчитывается по текущей цене газа.
   - Везём, только если выгодно: `стоимость токенов − (газ доставки + газ токенов + газ возврата) ≥ порога`.
     Иначе пометка «не выгодно».
   - Порядок в каждой сети:
     1. Сначала все доставки газа (каждая ждёт подтверждения).
     2. Затем кошельки, получившие газ: их токены, потом возврат остатка газа — только если остаток больше комиссии.
     3. Затем остальные кошельки.
     4. Автобус — последним.
   - Если доставка газа не прошла, токены с этого кошелька не отправляются.
4. **Ключи.** Вставь сиды или приватные ключи (формат как во вкладке «Добавить»). В памяти страницы остаются
   только кошельки, которые что-то подписывают по плану (включая автобус), остальное сразу выбрасывается. Ключи забываются после отправки,
   через 20 минут, по кнопке «Забыть ключи» и при закрытии вкладки. В localStorage, на сервер и на диск
   ничего не пишется.
5. **Отправка.** Окно подтверждения с предупреждением о связывании кошельков. Нужно повторить последние 6 символов
   адреса и поставить галочку. В каждой сети транзакции идут строго по одной, с ожиданием подтверждения;
   сети обрабатываются параллельно. У каждой транзакции виден статус и ссылка на эксплорер. Есть опция
   «остановить всё при первой ошибке». Журнал можно выгрузить кнопкой «Экспорт CSV».

**Важно.** Сбор со многих кошельков на один адрес навсегда связывает их в блокчейне, и антисибил-фильтры аирдропов
увидят их как одного человека. Адрес получателя сверяй посимвольно в самом приложении кошелька.

Настройки сетей (RPC, chainId, legacy, L1 fee): `public/sweep-chains.js`. CSP-заголовок разрешает странице
ходить только на эти RPC-хосты и `*.g.alchemy.com`.

## Тестирование на локальных сетях (без реальных денег)

Только публичные тестовые мнемоники (`abandon … about`, `test … junk`). Реальные сиды сюда не вставлять.

```bash
cd testchain
npm install          # один раз: hardhat + solc
npm run chains       # 3 локальные сети: 8545 EIP-1559, 8546 legacy, 8547 OP с мок-оракулом L1 fee (не закрывать)
npm run setup        # в другом окне: токены + балансы + фикстура testchain/data/
node verify.mjs snapshot
npm run panel        # панель в тестовом режиме: http://127.0.0.1:4778 (данные из testchain/data, data/ не трогает)
```

Дальше во вкладке «Сборщик»:
1. Получатель `0x70997970C51812dc3A010C7d01b50e0d17dc79C8`, затем «Построить план».
2. `node expect.mjs` — ручной расчёт плана; цифры должны совпасть с таблицей.
3. Вставь строки из `testchain/TEST-SECRETS.txt` → «Загрузить ключи» → «Отправить» → подтверди.
4. `node verify.mjs` — что реально переехало в сетях.

После этого проверь, что секреты нигде не осели:

```bash
grep -rlE "abandon|junk|1d8e676c" data testchain/data
```

Ожидаемый результат проверки (16.10.2026, фикстура с автобусом):
- План совпал с `expect.mjs`: придёт $664.95, суммы доставки газа и остатков — до последнего знака.
  Сверка: $669.39 в плане + $6.94 «не вошло» = $676.33 в панели, без остатка.
- «Акк 2» и «Акк 5» (токены без газа) получили газ от автобуса. «Акк 6» помечен «не выгодно»
  (доставка $0.24 против $1.20) и не тронут.
- Все 33 транзакции подтверждены. Порядок в блоках: доставки → кошельки с газом → остальные → автобус.
- На legacy-сети все отправлявшие кошельки, включая автобус, обнулены ровно до 0. На EIP-1559 остаётся пыль
  от запаса газа (~$0.002), на OP — ещё и L1-резерв (мок-оракул его не списывает).
- Прогон с ошибкой (до автобуса): «остановить при ошибке» остановил остальные шаги.
- grep ничего не нашёл. Страница не делала к серверу ни одного POST.
